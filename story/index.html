03 · Features

What you get when you hire Tim.

Four things I do on the job, with the proof where I have it.

  • 500K+ users moved from EWS to Microsoft Graph, across 500+ client companies
  • ~400 client companies migrated onto Exchange with zero data loss
  • 800+ → ~200 Jira tickets after my Claude triage skill cut the queue by 75%
  • 8 data recoveries for high-value accounts, on a runbook I designed

~30 escalations a month · 5–10 code fixes

Production escalations

I'm who production problems get escalated to. At MoxiWorks I was the engineering liaison to our Customer Support managers: a high-priority escalation came to me, and I owned it end to end, reproducing it, finding the root cause, shipping the fix and closing the loop with the customer.

That was about 30 escalations a month. I shipped 5–10 code fixes a month in the Rails codebase, resolved about 20 more with config changes or Rails console and SQL data repairs, and filed root-cause bug tickets so they didn't come back. When data loss was our fault, I ran the recovery runbook I designed: 8 recoveries for some of our heaviest-usage customers.

500K+ users · EWS → Graph · ~400 companies onto Exchange

Zero-loss data migrations

When Microsoft deprecated EWS, I led the cutover of all 500+ client companies (500K+ users) to the Microsoft Graph API, translating our stored Exchange IDs into Graph IDs. Every reachable mailbox made it; the only exceptions were deleted users and revoked authorizations.

I also led a mailbox migration onto Exchange for ~400 client companies: about 80% Exchange → Exchange (Microsoft 365 tenant to tenant) and 20% Google Workspace → Exchange, rebuilding the calendar, contact and group mappings with zero data loss. And I built the restoration pipeline: snapshot → SQL via kubectl → Rails rake task via Pulumi.

800+ → ~200 tickets · Jira → Claude → GitHub

AI-powered triage & review

I built a Claude skill, connected to Jira through the Atlassian MCP, that triages tickets every morning. It reads the description, separates by-design behavior from real bugs, asks reporters for missing details, and sends probes into our GitHub repo to cross-reference the code behind it, so an engineer starts with evidence instead of a blank ticket. It cut an 800+ ticket queue by 75% to about 200, each with clear repro steps, and became the team's daily priority list.

I also built Claude agent skills for PR authoring and code review that score each finding's likelihood of being a bug and mark it must-fix or minor, so the team ships smaller PRs more often. I review code alongside them. I also review PRDs and TRDs: I work deep in the product, and those docs are the instructions every feature is built from, so they have to be right before code gets written.

~20 staff · 24h → 1–2h partner onboarding

Self-serve tooling & automation

I built an AI diagnostic assistant on Claude, rolled out to about 20 Support and Customer Success staff, that turns vague bug reports into engineering-ready Jira tickets: repro steps, the affected account and sanitized details.

I automate the repetitive work too: my Node.js validation script cut partner onboarding from 24 hours to 1–2 hours. And I mentor support engineers on product architecture and mailbox-sync internals.
